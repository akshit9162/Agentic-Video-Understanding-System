Keyframes, one move at a time

Picking 25 of 80 sampled frames is a combinatorial search, so two policies edit a current selection, 40 moves per video.

  1. 01

    Which frame

    The horizontal policy picks one of the 25 to move.

  2. 02

    Which way

    The vertical policy moves it −1, +1, −5 or +5 sampled frames.

  3. 03

    Reward

    tanh(0.4·importance + 0.3·diversity + 0.3·coverage) on CLIP features.

  4. 04

    Summary

    Greedy moves from a random start, aimed at 20% of the running time.

What measurement showed

In deterministic rollout the policy collapses onto a few keyframe slots. Against TVSum’s human annotators, its CLIP-distance importance scores slightly below random: it rewards outlier frames over representative ones. The evaluation code lives in the reproduction.

That is why I rebuilt the published method from scratch: the PRLVS reproduction.

Asking a video questions

Transcript
Faster-Whisper, cached by the file’s SHA-256
Chunks
Up to 200 words, each keeps its timestamps
Index
bge-small-en-v1.5, one LlamaIndex index per video
Answer
Claude if a key is set, else the matching chunks alone

The Celery worker runs the single-process solo pool: native video libraries crash under fork on macOS.

Run it

Docker brings up the API, worker, Redis and a Streamlit front end. Without Docker, FFmpeg must be on PATH. CI runs the smoke tests on CPU-only PyTorch.

touch .env   # API keys optional
docker compose up --build

# or without Docker
pip install -r requirements.txt
redis-server &
celery -A celery_app worker --pool=solo &
uvicorn app.api:app --reload
