System walkthrough

Long video in, a playable summary and a searchable transcript out.

An RL policy picks keyframes, scene detection turns them into clips, and FFmpeg stitches the summary back with the original audio. Whisper transcribes speech, and a LlamaIndex RAG layer answers questions about the video with timestamps. It all runs as async jobs behind FastAPI, Celery and Redis, with progress streamed over SSE.

How a request flows

End-to-end pipeline

Uploads and YouTube URLs both become a Celery job, so the API returns a task id at once and never blocks on inference.

01IngestMP4 upload or YouTube URL via yt-dlp
02EmbedSample frames and embed each with CLIP ViT-B/32
03SelectTwo-level RL policy refines 25 keyframes
04ReconstructPySceneDetect maps keyframes to scenes; OpenCV writes clips
05MergeFFmpeg re-attaches the original audio track
06TranscribeFaster-Whisper, cached by SHA-256 of the file
07AskLlamaIndex index over transcript chunks, answers with timestamps
Keyframe selection

A hierarchical action space

Choosing K frames out of N directly is a combinatorial search. The agent instead edits a current selection, one frame at a time.

Horizontal policy

Chooses which of the 25 selected frames to move.

Vertical policy

Chooses how to move it: −1, +1, −5 or +5 frames.

Reward

tanh(0.4·importance + 0.3·diversity + 0.3·coverage), where importance comes from CLIP-embedding distance statistics.

Inference

A deterministic rollout of the trained policy gives a stable summary for each video.

What measurement showed. In deterministic rollout, the trained policy collapses onto a small number of keyframe slots. Its CLIP-distance importance signal scores slightly below random against TVSum human annotators, because it rewards outlier frames over representative ones. That finding led to a separate project: a from-scratch reproduction of the published method the policy is based on, PRLVS.
Grounded Q&A

Asking questions about a video

Transcripts are split into chunks of up to 200 words, each keeping its start and end timestamps, then embedded with BAAI/bge-small-en-v1.5 into a LlamaIndex vector index persisted per video. Answers cite the timestamp ranges they came from.

Retrieval

POST /rag/query searches that video’s index, which is built once when the video is transcribed and then reused.

Generation

Claude when ANTHROPIC_API_KEY is set, OpenAI as a fallback, and retrieval-only output otherwise.

Transcript insights

A LangChain runnable (prompt → LLM → parser) returns a 3–5 bullet summary, or an extractive summary when no key is set.

Celery runs with a single-process solo worker pool, because native video libraries crash under fork-based multiprocessing on macOS. A Streamlit front end uses this API.

Local setup

Run it locally

docker compose up --build        # API, worker and Redis
# or, without Docker:
pip install -r requirements.txt
redis-server &
celery -A celery_app worker --pool=solo &
uvicorn app.api:app --reload
streamlit run app/streamlit_app.py

CI (GitHub Actions) installs CPU-only PyTorch and runs the smoke tests in tests/ on every push to main.
